# Recording and recovery

`preview` and `build` are offline. Only `burn`, `erase` and explicit calibration
recording write to a disc. Recording currently uses macOS DiscRecording.

## Normal workflow

```sh
discimage preview album.toml
discimage build album.toml
open output/album/preview.svg
discimage devices
discimage burn output/album
```

The default output is `output/<TOML filename>/`, beside that TOML. Use `build -o`
only to override it. CD-R and CD-RW configurations can share original audio and
artwork while producing separate `output/cdr/` and `output/cdrw/` packages.

A package is flat: `01.wav`, `02.wav`, `artwork.png`, `preview.svg` and one
`manifest.toml`. The manifest stores frozen project settings, input hashes and
recording state. Optional companion files are stored once as numbered flat files;
their original ISO paths and empty directories are preserved in the manifest.
No provisional ISO or RAW is generated by default.

`build` replaces only an unstarted or completed managed package, after the new
one verifies. Unfinished/uncertain recordings and extra private files block
replacement. A failed build retains the previous package. Never hand-edit a
recording package; edit the album and rebuild before writing.

## Drive and medium

`devices` displays hardware IDs, backend, disc status, capabilities and tracks.
`select ID` saves a default; `--device ID` overrides one operation. Missing or
ambiguous IDs stop the operation. New recordings may use the only eligible blank
drive. Once a recording is bound, its drive and requested speed stay fixed.
`build` ignores drive selection and never accesses optical hardware.

```sh
discimage select DRIVE_ID
discimage burn output/album             # Automatic speed.
# Or explicitly choose one drive and speed for a new recording:
discimage burn output/other --device DRIVE_ID --speed 10
```

Presets can specify `media = "cd-r"` or `media = "cd-rw"`. A mismatch stops before
writing. Capacity and geometry in the preset are reference values; the drive's
actual capacity and NWA are checked independently. Inputs are normalized to
sector-aligned PCM. Decoder tail padding and required drive gaps are checked
before writing and recorded in the frozen settings.

## Reusing CD-RW

```sh
discimage erase --dry-run
discimage erase
```

Check the displayed drive and disc, then type `ERASE`. Full erase is the default;
`--quick` only resets metadata and may leave old artwork. CD-R is rejected.
Erasing confirms a blank medium with writable capacity and does not start a burn.
DRErase cannot be aborted: after starting, the CLI waits and reports progress.
Keep the drive connected until completion.

## Recording transaction

1. Verify frozen inputs, select the expected blank medium and reserve the drive.
2. Persist the write intent, write appendable audio, then compare recorded PCM
   byte-for-byte against the prepared tracks. Failure blocks the data write.
3. Read the actual next writable address. Missing or ambiguous NWA stops the
   recording; no estimate or arbitrary offset is substituted.
4. Generate only data and its preview in a temporary `.work/` directory. The
   audio and artwork are reused. Verify the generated data, promote the files,
   update the manifest and remove temporary files.
5. Recheck NWA and remaining space, write the cooked ISO, verify and finalize.
   Require the original music layout and a data track in session 2.

After success, one actual `session2.iso` and the updated preview remain beside
the inputs. RAW is retained only when explicitly requested. macOS does not send
RAW to the drive. Physical artwork and player behavior still need inspection.

The manifest is replaced atomically and synced before native writes. A package
lock prevents simultaneous build/burn operations. Temporary replacements retain
an old package if promotion fails; an interrupted swap is preserved for recovery.

## Recovery

Run the same `burn PACKAGE` command. `music_written` verifies audio and reads NWA
without writing the music again. `data_ready` reuses a verified image only if its
NWA and capacity still match; otherwise it regenerates data alone.
`music_writing` and `data_writing` are uncertain and refuse automatic retry.
Completed recordings cannot be burned again; rebuild for another blank disc.

Old v1 jobs retain their recovery path. A completed non-calibration job can be
verified and flattened with `verify OLD_JOB --compact`. Migration verifies the
old manifest, PCM and images, preserves the exact written ISO and only replaces
the old directory after the flat package verifies. Calibration evidence is not
rewritten because its original manifest hash is part of the measurements.

## Image export, local checks and CD-Text

`build --iso` exports cooked data; `build --raw` exports Mode 1 RAW with framing
and EDC/ECC. Without a measured `--session-start LBA`, these are estimates.
Audio remains separate. `verify PACKAGE` checks inputs and any exported image.
`verify PACKAGE -o encoded.png` optionally projects the encoded payload from
ISO or RAW. It is a local check and optical appearance is not simulated.

Optional `[cd_text]` writes the album title, performer and track titles. Use
printable ASCII; preparation rejects fields the framework would alter. WAV tags
do not become CD-Text automatically. Use `drutil cdtext` after recording to read
it back on a capable drive.

Logs use Terminal.app-compatible ANSI colors, plain redirected text and
`NO_COLOR=1`. Progress includes phases, available percentages, speed and elapsed
time; a slow drive operation continues reporting a heartbeat.
